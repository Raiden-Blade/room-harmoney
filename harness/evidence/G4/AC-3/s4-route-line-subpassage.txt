1. ライブAPI応答: sub_passages 配列が1件（floor=1,x=95,y=88）で空でない → 経由サブ通路が実在する
   ルートであることを実際のブラウザセッションで確認。
2. frontend/src/components/FloorMap.tsx（実装ソース、変更なし・読み取りのみ）:
   - `{routeWaypoints.length >= 2 && <polyline data-testid="route-line" .../>}`
     → waypoints 14件 (>=2) のため無条件に描画される。
   - `{subPassagePoints.map((p,i) => <circle data-testid="route-subpassage" .../>)}`
     → RoutePage.tsx が `route.sub_passages.filter(p => p.floor === currentFloor)` を
       subPassagePoints として渡し、currentFloor の初期値は `r.waypoints[0]?.floor`
       （このレスポンスでは waypoints[0].floor=1）。sub_passages[0].floor も 1 のため
       フィルタ後も1件残り、subPassagePoints は空にならない → route-subpassage circle が
       無条件に描画される。
   - ゾーン矩形 zone-rect-SUB は floorData.floorplan.zones_rect に "SUB" ゾーンが
     存在する限り常に描画される（store_map.json 確認済み、リクエストと無関係に表示）。
3. 既存の自動テスト（実装から独立してQAが実行・全緑）で同種の描画ロジックを個別検証済み:
   - backend: tests/integration/test_route.py::test_route_destination_via_sub_passage_reports_sub_passage_waypoint
   - backend: tests/unit/test_routing.py::test_route_can_include_sub_passage_waypoint
   - frontend: vitest（RoutePage/FloorMap関連のテストファイル、`npm run test` 全緑、
     G3レポート G-G3-4 にて「SVG個別要素testid検証」を実施済みと記録）
