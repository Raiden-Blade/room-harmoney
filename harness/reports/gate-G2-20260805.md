### G-G2-2（単体デグレ無し）
`tests/unit` 24件すべて PASSED。G1レポート（gate-G1-20260805.md）と同数・同結果で、
デグレは検出されなかった。

### G-G2-3（実質性レビュー）
41件全件を読解し、各テストが具体的な期待値（レスポンスボディの厳密比較、DB直接読み出しに
よるイベント内容確認、エラーコード文字列の厳密一致）をアサートしていることを確認した。
`assert response.status_code == 200` のみで終わる空アサートは皆無。特に
`test_recommendations_related_are_sorted_by_lift_descending` はリフト値の列
`[1.3,1.3,1.3,1.2,1.2,1.2,1.0,1.0]`まで固定値比較しており、並び順ロジックが壊れれば
確実に検出できる構造になっている。詳細は evidence/G2/G-G2-3/review.md 参照。

### G-G2-4（来店ロック AC-5）
`recommendations`/`route` の両エンドポイントについて、(a) session_id無し、(b) 実在しない
session_id、の両ケースで 409 + `code=VISIT_LOCK_REQUIRED` を確認。有効セッション
（`POST /api/session`で発行）を渡した場合は200で成功することも確認。
uvicorn実サーバでの独立追加検証でも同結果を再現（evidence/G2/G-G2-9）。
`app/dependencies.py::require_active_session` が両ルータに `Depends` で結線されている
実装であることもコードで確認した。

### G-G2-5（experiment_group AC-4）
`POST /api/session` のレスポンスに `experiment_group` が付与されることに加え、
`session_start` / `related_view` / `route_view` / `coordinate_view` / 任意の
`POST /api/events` のすべてで、DBに記録されたイベント行の `experiment_group` が
そのセッションの割付値と一致することをテストコードが `store.list_events()` で
直接検証している（レスポンスの自己申告のみに依存していない）。
クライアントが `experiment_group` を payload に含めなくてもサーバ側で必ず付与される
ことも確認済み（クライアント偽装耐性）。実HTTPでも event_id 1→2→3 の連番で
`experiment_group="control"` が一貫して付与されることを確認した。

### G-G2-6（エラーコード 19章）
不正qr_id・存在しないproduct_id/coordinate_id・範囲外floor・許可外event_type・
未知session_id が、いずれも明確なHTTPステータス＋`{"code":...,"message":...}`の
統一フォーマットで返ることを確認。「経路なし（ROUTE_NOT_FOUND）」のみ実データが
全ノード連結（G1で確認済み）のため通常操作では再現できず、QAが
`route_builder` を dependency_overrides で「常に到達不能」を返すスタブに差し替える
自作リクエストで独立検証し、`404` + `code=ROUTE_NOT_FOUND` を確認した
（実装コードは一切変更していない。テスト実行後にoverrideは解除済み）。

### G-G2-7（副作用なし）
`tests/unit`・`tests/integration` 実行前後で `data/*.json` 全7ファイルのmd5ハッシュが
完全一致することを確認した（結合テストは `tests/integration/conftest.py` の
`isolated_store` フィクスチャで `tmp_path` 配下の隔離SQLiteを使用しており、
本番/開発用DBファイルを一切生成しない設計）。pytest実行のみでは `.db` ファイルは
リポジトリに残らなかった。なお G-G2-9 のuvicorn実サーバ起動検証時にのみ
`data/room_harmony.db` が新規生成されたが、これはQAが独立検証のために意図的に
起動したライブサーバの副産物であり、検証後に削除しリポジトリをクリーンな状態に
戻した（`.gitignore` にも `*.db` が登録済みであることも確認）。

### G-G2-8（OpenAPI）
`scripts/export_openapi.py` を実行し `docs/openapi.json` が生成されることを確認。
生成後のmd5は実行前と一致（既に最新化されていた＝決定的な出力）。含まれるパスは
`POST /api/session`, `GET /api/qr/{qr_id}`, `GET /api/products/{product_id}`,
`GET /api/recommendations`, `GET /api/coordinates/{coordinate_id}`, `GET /api/route`,
`GET /api/store-map/{floor}`, `POST /api/events`, `GET /health` の9件（17章記載の
8エンドポイント全てを含む）。

### G-G2-9（独立実応答）
uvicorn (`127.0.0.1:8811`) を実起動し、テストコードを一切経由しない実HTTPリクエストで
以下を確認した。
1. `POST /api/session {"qr_id":"QR-ENTRANCE-001"}` → 200、`experiment_group="control"`
2. `GET /api/recommendations?product_id=P027&session_id=<上記>` → related のlift列が
   `[1.3,1.3,1.3,1.2,1.2,1.2,1.0,1.0]`で非増加（リフト降順）
3. `POST /api/events`（chatbot_open）→ `event_id=3`、`experiment_group="control"`
   （session_start=1, related_view=2 に続く3件目、一貫して同じexperiment_group）
4. `GET /api/route?from_qr=QR-ENTRANCE-001&to_product=P001&session_id=<上記>` → 200、
   入口座標(3,50)からP001座標(17,18)への5ウェイポイント経路
5. `GET /api/recommendations?product_id=P001`（session_id無し）→ 409 + `VISIT_LOCK_REQUIRED`

サーバは検証後に停止し（PID 12636 を taskkill）、生成された `data/room_harmony.db` は削除済み。
