## G-P3A-3: テスト実質性（ハリボテでないこと）

`test_personalized.py` / `test_recommendations_personalized.py` を読み、以下がいずれも
具体値でのアサーションになっており、モック丸投げ・ステータスコードのみの確認（ハリボテ）
ではないことを確認した（実装コードは変更していない）。

- **後方互換（base一致）**: `test_no_member_id_matches_base_exactly` /
  `test_unknown_member_id_matches_base_exactly` /
  `test_member_with_empty_purchase_history_matches_base_exactly` の3件が、
  `PersonalizedRecommender.recommend()` の戻り値を `base.recommend()` の戻り値と
  `==` で完全一致比較し、かつ関連商品の並び `["PC", "PB"]` を具体的に検証している。
  さらに `test_passthrough_returns_the_exact_base_object_instance` は、スタブbaseが
  返す同一オブジェクトを `is` で恒等性チェックしており、「値がたまたま同じ」ではなく
  「base結果をそのままreturnしている」という実装方針そのものを検証している。
  結合テスト側も `test_recommendations_with_unknown_member_id_matches_base_order` /
  `test_recommendations_with_empty_history_member_matches_base_order` がAPI応答の
  `related` 配列をJSON丸ごと比較している。
- **アフィニティ再ランク**: `test_affinity_member_changes_ranking_order` は
  `score == 1.0 * (1 + 0.15 * 5)` のように、重み・購入回数から手計算した期待値と
  実際のスコアを一致比較しており、並び変化（`["PB","PC"]`）だけでなく数値の正しさまで
  検証している。結合テスト側 `test_recommendations_with_affinity_member_reorders_related`
  も、サンプルデータM004（カーテン3回購入）でカーテンのcat_midがキッチン雑貨より上位に
  来ることを `cat_mid` の並び列で厳密比較し、`lift` 自体は不変であることも確認している。
- **member_id非保存**: `test_member_id_is_not_persisted_in_events` は
  `event["payload"]` に `member_id` キーが無いことだけでなく、イベント行全体を
  `json.dumps` した文字列に `"M004"` という値そのものが一切出現しないことまで
  網羅的にチェックしており、キー名変更等で紛れ込ませる抜け道も塞いでいる。
- **決定性**: `test_deterministic_repeated_calls_return_equal_results` は同一入力で
  2回呼び出し、順序・スコアの両方をリスト比較している。

判定: **PASS**（いずれも実質的なアサーションを持ち、ハリボテではない）

## G-P3A-6/7: プライバシー（events DB直読み）／来店ロック無回帰（QA自作・実HTTP+DB直読み）

QAが新規作成したスクリプト（`harness/evidence/P3A/qa_p3a_privacy_check.py`）で、
`fastapi.testclient.TestClient` から隔離した実SQLiteファイル（`tempfile.mkdtemp`配下）に
対して以下を実行した。

**G-P3A-7（来店ロック無回帰）**:
- `session_id` 無し + `member_id=M004` 付き → **409 `VISIT_LOCK_REQUIRED`**（確認）。
- 存在しない `session_id`（bogus）+ `member_id=M004` → **409**（確認）。
- `member_id` クエリの有無が来店ロック判定（`require_active_session`）に一切影響しない
  ことを確認。

**G-P3A-6（プライバシー・独立確認）**:
- 有効セッションを作成し `GET /api/recommendations?product_id=P027&member_id=M004` を実行
  → `200`、`personalized: true`。
- `Store.list_events()` 等の実装側メソッドは使わず、**`sqlite3` で当該DBファイルを直接
  接続**し、`sqlite_master` から全テーブル（`sessions`, `events`, `sqlite_sequence`）を
  列挙、**全カラムを丸ごとダンプ**して文字列 `"M004"` の出現有無を検索した結果、
  **DB全体（セッション行・イベント行のいずれにも）"M004" は一切出現しない**ことを確認。
- `events` テーブルの `related_view` 行の `payload` カラム（JSON）を直接パースし、
  キー集合が `{product_id, related_product_ids, coordinate_ids, personalized}` の
  4つのみであること（`member_id` キーが存在しないこと）を確認。
- APIレスポンスJSON自体にも `"M004"` という値が出現しないことを確認（会員IDをそのまま
  レスポンスに含めない設計）。

判定（両方）: **PASS**（証跡: `harness/evidence/P3A/G-P3A-6_7_privacy_and_lock_check.txt`。
最終実行では PASS 14 / FAIL 0）。
