### G-P2B2-3: テスト実質性の精読確認
`AdminDashboardPage.test.tsx`（7ケース）を精読し、以下が実際にアサートされていることを確認した
（定数のみを検証する空虚なテストではない）。

- **群別ファネル**: `session-count-treatment`/`control` の件数、`kpi-funnel-svg` 内の
  `rect[data-testid^='kpi-funnel-bar-']` が **8本**（4段階×2群）であることを厳密にカウント。
- **率（rates）**: `rate-row-related_tap_rate-treatment/control` の `%` 表示値をピンポイントで検証
  （`60.0%`/`40.0%`）。
- **diff の符号**: `rate-row-related_tap_rate-diff` が `+20.0pt`（正の差分に `+` 符号）であること、
  かつ `toHaveClass("kpi-diff-positive")` でCSSクラスまで検証。負の差分ケース（POSの一部欠損
  テストではなく通常時のマイナス方向のケースは本ファイルには無いが、実ブラウザ確認で
  `-50.0pt`／`kpi-diff-negative` 相当のマイナス符号表示を筆者が別途実データで確認済み＝下記
  G-P2B2-4 参照）。ゼロ差分時の `±0.0pt` は `formatDiffPercentPoint` のロジックとして
  実ブラウザ確認（サブ通路通過率 A/B差分が実データで `0.0` の場合に `±0.0pt` 表示）で確認。
- **sub_passage_rate**: `sub-passage-rate-treatment/control`（`25.0%`/`10.0%`）と
  `sub-passage-rate-diff`（`+15.0pt`）を個別にアサート。
- **POS null → N/A**: `pos-metrics-na` が表示され `pos-metrics`（テーブル）が
  `not.toBeInTheDocument()` であることを確認するテストケース、および POS一部指標のみ
  `null` の場合に該当セルのみ `N/A` になり他は数値表示のままであることを確認するテストケース
  （`pos-row-items_per_purchase-treatment` のみ `N/A`、`pos-row-co_purchase_rate-treatment` は
  `32.0%`）の2ケースが存在。
- **401ハンドリング**: `route()` モックで `X-Admin-Token` ヘッダー不一致時に `status: 401` を返す
  実装を使い、`admin-auth-error` が表示され `admin-kpi-content` が
  `queryByTestId(...).not.toBeInTheDocument()` であることを確認。`fetchMock` が
  ちょうど1回しか呼ばれていないこと（`toHaveBeenCalledTimes(1)`）も検証しており、
  余計な再試行が無いことまで確認している。
- **SVGバー描画**: `funnelSvg.tagName.toLowerCase()` が `"svg"` であること、バー要素数
  （8本）、各バーの `aria-label` に実測値の文字列が含まれることを確認しており、
  「描画されているように見えるだけ」ではなく実際のDOM構造・属性値まで検証している。
- **空データ状態**: 両群 `session_count: 0` の場合に `admin-kpi-empty` が表示され、
  `kpi-funnel-svg` が描画されない（`not.toBeInTheDocument()`）ことを確認。
- **未入力時**: `fetchMock` が一度も呼ばれない（`not.toHaveBeenCalled()`）ことまで確認しており、
  「入力前にAPIを叩かない」という重要な仕様を単なるUI表示だけでなくネットワーク未発火のレベルで
  検証している。

以上より、ハリボテ（定数だけを検証する空虚なテスト）ではなく実質的な検証が行われていると判断した。

### G-P2B2-4: 実ブラウザ到達（Claude_Browser MCP）
backend（`uvicorn app.main:app --port 8000`）・frontend（`npm run dev`、5173番）を起動し、
Browser MCP で `http://localhost:5173/admin` へ navigate して以下を確認した。

**スクリーンショット取得可否**: 本環境では `computer{action:"screenshot"}` および `zoom` が
`Screenshot timed out after 5s: the Browser pane is not displayed, so the page is not
compositing frames.` で一貫して失敗した（Browser pane が可視状態でないため）。このためHARNESS.md
の指示どおり、**テキスト／アクセシビリティツリー（`get_page_text`／`read_page`）を証跡とする**。

1. **未入力時のプロンプト（KPI非表示）**: `get_page_text` で
   `管理トークンを入力してください。` が表示され、KPIセクション（`admin-kpi-content` 相当の内容）
   が一切表示されていないことを確認（evidence/P2B2/G-P2B2-4_unauthenticated_page_text.txt）。

2. **正しいトークンでのKPI表示**: 管理トークン欄に `dev-admin-token-change-me` を入力し
   「KPIを取得」をクリックしたところ、`GET http://localhost:8000/api/admin/kpi` が
   実際に発火し200が返り、群別セッション数・ファネル（QRスキャン→関連商品表示→タップ→
   ルート表示）・主要な率（率テーブル＋**diff**、`-50.0pt` のようにマイナス方向の符号も
   実データで確認）・サブ通路通過率（感覚値10%との比較）・POS突合（併売率／買上点数／客単価、
   `data/pos_metrics.json` 実データに基づく非null値と診断diff）・因果注記（`kpi.note` の全文）
   がすべて表示されることを `get_page_text` で確認した
   （evidence/P2B2/G-P2B2-4_authenticated_page_text.txt）。
   さらに `read_page`（アクセシビリティツリー）で `KpiBarChart` の各SVG `<rect>` が
   `role="img"` ＋ `aria-label="利用群（treatment） QRスキャン: 1件"` 等の形で**実際にDOMへ
   描画**されていることを確認（ハリボテのSVGでなく実測値が反映されている）。
   ページ表示内容とバックエンドを直接 `curl` した応答JSONを突合し、数値が完全一致することも
   確認した（率・diff・POS値まで一致）。

3. **誤トークンでの認証エラーUI**（詳細は下記「G-P2B2-4 詳細」を参照）: 実ブラウザでのクリック
   起点の再現を複数手法（クリック／`Tab`+`Enter`／フォーム直接値設定＋クリック等、計10回超の
   試行）で試みたが、いずれも新規の `/api/admin/kpi` リクエストが発火せず、
   `computer{action:"screenshot"}` と同根とみられる **Browser pane 非表示に起因する入力デリバリの
   制約**（新規に開いたタブは `Viewport: 0x0` のまま固定され、`left_click` がビューポート外の
   座標（例: `(-33, -445)`）に解決される事象を確認）により、実ブラウザでの「クリック操作起点」の
   401エラーUI再現はできなかった。これはアプリ側の不具合ではなく本QA実行環境の制約と判断し、
   以下の代替証跡で同等の厳密さを担保した。
   - バックエンド `curl` で `X-Admin-Token` 無し／誤りの両方が **401
     `ADMIN_UNAUTHORIZED`** を返すことを直接確認（evidence/P2B2/G-P2B2-4_backend_401_curl.log）。
     フロントの `client.ts`（`getAdminKpi`）はこのレスポンスを `ApiError(status=401)` として
     投げ、`AdminDashboardPage.tsx` の `fetchKpi` の `catch` 節で
     `err.status === 401` のとき `admin-auth-error` を表示し `kpi` を `null` にする実装を
     コードレビューで確認済み（`AdminDashboardPage.tsx:119-128`）。
   - この同一実装コード・同一分岐を、G-P2B2-2/3 で確認した vitest（`AdminDashboardPage.test.tsx`
     「誤ったトークン（401）では取得失敗UIを表示し、KPIは描画されない」ケース）が
     実際に**実行してPASS**しており、`admin-auth-error` の表示・`admin-kpi-content` の非表示・
     `fetchMock` 呼び出し回数まで検証済み。jsdom+React Testing Libraryは実DOMイベント
     （`fireEvent.click`）と実Reactコンポーネントツリーを用いるため、Browser paneの表示制約を
     受けない代替経路として実質的な検証力を持つと判断した。

### G-P2B2-5: 顧客導線と分離
`frontend/src/App.tsx` のルーティングコメントに「`/admin`: ...来店客のS1〜S5フローとは分離した
導線で、顧客向け画面からはリンクしない（直リンク前提）」と明記されていることに加え、
`grep -rn "admin" frontend/src` の結果、`/admin` への参照は
`App.tsx`（ルート定義）、`AdminDashboardPage.tsx`（自身）、`client.ts`（API呼び出し）、
`adminAuth.ts`（トークン保存）、`schema.ts`/`types.ts`（型定義）のみであり、
`ScanPage.tsx`／`ProductPage.tsx`／`CoordinatePage.tsx`／`RoutePage.tsx`（顧客向けS1〜S4画面）の
いずれにも `/admin` へのリンク（`<Link to="/admin">` 等）や `href` は存在しないことを確認した。
`/admin` は直リンク（URL直接入力）でのみ到達可能であり、顧客導線とは分離されている。

### G-P2B2-6: POS N/A 経路
`AdminDashboardPage.tsx` の該当ロジック（`kpi.pos_metrics` が `null`/`undefined` の場合に
`<p data-testid="pos-metrics-na">POSデータ未連携（N/A）</p>` を表示し、テーブル自体を
描画しない）をコードレビューで確認。加えて `AdminDashboardPage.test.tsx` の
「正しいトークンでKPIを取得し...」テストケースで `pos_metrics: null` のレスポンスに対し
`pos-metrics-na` が表示され `pos-metrics`（テーブル）が
`not.toBeInTheDocument()` であることを実行・PASS確認済み。さらに「POSの一部指標のみ欠損」
テストケースでは、`items_per_purchase: null` のみが `N/A` になり、他の指標
（`co_purchase_rate`）は通常どおり数値表示される（欠損に強い設計）ことも確認した。
なお実ブラウザ確認（G-P2B2-4）では `data/pos_metrics.json` に実データがあるため
POS全項目が非null値で表示され、N/A分岐は通っていない（テストでのみ確認、と明記）。

## 補足所見（FAILではないが記録・環境制約）
- 本QA実行環境の Browser MCP は `screenshot`／`zoom`（コンポジット描画）に非対応
  （`the Browser pane is not displayed, so the page is not compositing frames.`）。
  さらに、最初に開いたタブ（`seed`）以外の新規タブは `Viewport: 0x0` に固定され、
  座標ベースのクリック（`left_click`）が画面外座標に解決される事象を確認した。
  これにより「誤トークン→401エラーUI」の**クリック操作起点**での実ブラウザ再現のみ、
  vitest（RTL）テスト＋バックエンド直curlでの代替検証とした（詳細は G-P2B2-4 参照）。
  それ以外（未入力プロンプト・正トークンでのKPI全項目表示・SVGバー描画・値の突合）は
  実際に `seed` タブ上でクリック・入力・実ネットワーク往復を伴う形で確認できている。
  この制約はアプリ実装の不具合ではなく、QA実行環境（Browser pane 非表示）に起因すると判断した。
