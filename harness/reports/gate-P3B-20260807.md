## G-P3B-3 詳細（テスト実質性の確認）

`test_visit.py`・`test_visit_verification.py` を読了し、以下がハリボテでなく実際に
アサートされていることを確認した。

- **geofence半径判定**: `TestGeofenceVerifier` は境界ちょうど（150m）が合格（`<=`）、
  境界+1mが不合格になることを、緯度オフセットの解析的厳密値（`R * radians(Δφ)`）から
  逆算した座標で検証している（ハードコードされた期待値の丸暗記ではない）。
  QA独立スクリプトでも同じ境界を別実装で再現し一致（G-P3B-5参照）。
- **wifi一致**: `TestWifiVerifier` は一致/不一致/None/空文字/キー欠如の5パターンを
  `reason` フィールド込みでアサート。
- **モード合成**: `TestResolveVerifier` は `qr+geofence`/`qr+wifi`/`qr+geofence+wifi`
  それぞれについて「両方OK→OK」「片方NG→NG」の複数ケースを実引数で検証。
  未知トークン（`"totally-unknown-mode"`）が安全側（QR必須）にフォールバックすることも
  検証しており、設定ミスへの配慮まで踏み込んでいる。
- **既定qr無回帰**: `test_default_qr_mode_passes_without_any_location_signal`
  （単体）と `test_default_qr_mode_without_location_signals_still_works`
  （結合・実際に`/api/session`→`/api/recommendations`→`/api/route`まで通す）の両方が
  存在し、位置シグナル無しでも既定モードが通ることを実エンドポイント経由でも確認。
- **プライバシー非保存**: `test_location_and_wifi_signals_are_never_persisted_in_events`
  は `events` の全payloadキーに対して禁止キー集合(`location`, `location_lat`,
  `location_lng`, `wifi_ssid`, `lat`, `lng`, `ssid`)との積集合が空であることに加え、
  payload全体を文字列化して実座標値・実SSID文字列そのものが含まれないことまで検証して
  おり、キー名だけでなく値の漏洩も検査している。対で
  `test_location_and_wifi_are_persisted_in_sessions_table_for_verification` があり
  「events非保存」と「sessions保持」を対比的に検証している＝意図的な設計と読める。

以上より、いずれのテストも実装の内部状態・実際のAPIレスポンス・DBの生データに対する
具体的なアサーションを持ち、ハリボテ（常にPASSする無意味なテスト）ではないと判断した。

## docs/openapi.json の反映状況（所見）

`docs/openapi.json` の `CreateSessionRequest` スキーマを確認したところ、フェーズ3-Bで
`schemas.py` に追加された任意フィールド `location`（`LocationSignal`: lat/lng）・
`wifi_ssid` が**反映されていない**（`qr_id` のみのまま。`LocationSignal` スキーマ定義
自体が存在しない）。同様に、これを元に `npm run gen:api` で生成される
`frontend/src/api/schema.ts` の `CreateSessionRequest` 型も `qr_id` のみで、
フロント側の型定義にも反映されていない。

**FAIL要否の判断**: 本フェーズ(P3-B)はDECISIONS #7のとおりbackendのみの変更であり、
フロントは`location`/`wifi_ssid`を送信する実装を持たない（`frontend/src`を検索したが
該当なし）。従って現時点でこの型不整合が実際の機能不具合・回帰を引き起こしてはおらず、
G-P3B-1〜7のいずれの受け入れ基準にも抵触しないため、**この所見単体ではP3-Bゲートを
FAILにしない**。ただし、`docs/openapi.json`はAPI仕様のドキュメントとして実装と乖離した
状態であり、今後フロントでこれらのフィールドを利用する際の型生成にも影響するため、
実装エージェントに以下を指摘として送る。

- 指摘: `backend/scripts/export_openapi.py` を実行して `docs/openapi.json` を
  再生成し、`CreateSessionRequest.location`（`LocationSignal`）・`wifi_ssid` を
  反映すること。必要であれば `frontend` 側で `npm run gen:api` も再実行し、
  `src/api/schema.ts` を同期すること。
