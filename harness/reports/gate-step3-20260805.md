## 詳細所見

### G-S3-1（backend 結合スモーク）
`backend/tests/integration/test_health.py::test_health_returns_200_and_ok_status` が PASS。
`FastAPI TestClient` 経由で `/health` が 200 と `{"status": "ok"}` を返すことを確認。
警告（`StarletteDeprecationWarning: httpx2 推奨`）が出ているが、テスト結果には影響なし。

### G-S3-2（backend サーバ稼働）
`uvicorn app.main:app --port 8000` を実際に起動し、`curl -i http://127.0.0.1:8000/health` で
`HTTP/1.1 200 OK` および本文 `{"status":"ok"}` を確認。加えて Browser MCP で
`http://127.0.0.1:8000/health` に navigate し、ページ本文が `{"status":"ok"}` であることも確認（二重確認）。
確認後、`Stop-Process` でサーバプロセスを停止済み（残存プロセスなし）。

### G-S3-3（frontend ビルド）
既存の `frontend/dist` を検証前に削除し、`npm run build`（`tsc -b && vite build`）を実行して
クリーンな状態からビルドが成功することを確認。`dist/index.html`, `dist/assets/index-*.css`,
`dist/assets/index-*.js` が生成された（`node_modules` は既に導入済みだったため `npm install` は不要だった）。

### G-S3-4（frontend 表示・任意）
`npm run preview -- --port 4173` で `dist` を配信し、Browser MCP で `http://localhost:4173` に
navigate。タブタイトルは "Room Harmony"、`get_page_text` の結果は
「Room Harmony / 来店客向けアプリ Room Harmony（開発中）」、`read_page`（アクセシビリティツリー）でも
`heading "Room Harmony"` を確認。表示自体は成功と判断し PASS とした。

**証跡形式についての注記**：本タスクの指示は「ブラウザMCPで開いて...スクショで残す」だが、
本実行環境では `computer screenshot` アクションが
`"the Browser pane is not displayed, so the page is not compositing frames"` という理由で
一貫してタイムアウト（画面合成が有効化されていない）し、PNG スクリーンショットを取得できなかった。
これはアプリ側の不具合ではなく検証環境（Browser ペインの表示状態）の制約である。
代替として `get_page_text` と `read_page`（アクセシビリティツリー）によるテキストベースの証跡を
`harness/evidence/step3/G-S3-4/frontend-page-text.txt` に保存し、表示内容を確認した。
スクリーンショットでの証跡が必須要件である場合は、Browser ペインを表示可能な環境で再実行し
PNG を追加取得することを推奨する（実装側の指摘事項ではない）。
