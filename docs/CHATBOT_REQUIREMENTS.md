# Room Harmony ガイド型チャットボット要件

## 1. 目的

本機能の目的は、会話回数やAIらしさを増やすことではない。店頭で商品QRを読み取った来店客が、短時間で「同じ空間に置く候補」を理解し、複数商品の売場案内へ進めるようにすることである。最終KPIは同一空間商品の併売率であり、チャットの利用率は中間指標として扱う。

## 2. 課題資料からの制約

| 資料上の論点 | 実装要件 | 検証方法 |
|---|---|---|
| 目当ての商品以外を見ない | QRで起点商品を確定し、関連候補を会話開始時から提示する | 商品IDのないチャットを作らない |
| 自分で入力・探索することを億劫に感じる | 空欄の自由入力だけにせず、回答しやすい選択肢を1問ずつ表示する | 初回応答と質問数をテストする |
| 関連商品の認知度が低い | 商品名だけでなく、候補になった理由と売場への導線を返す | API・画面・ルート連携を結合テストする |
| 同一空間商品の併売率を上げる | 既存の併売リフトとコーディネート候補を推薦の主信号に保つ | 既存推薦器の回帰テストを維持する |
| 店頭Webとして実現可能であること | 外部LLMを必須にせず、Pythonのルール・テンプレートで低遅延に動かす | API応答時間と外部通信なしを確認する |
| 費用対効果を説明できること | 既存データ・既存API・既存ルートを再利用し、新しい学習基盤を前提にしない | 依存関係と運用条件をREADMEに明記する |

## 3. 初版の機能境界

### 実装する

- 商品QRから引き継いだ商品文脈での相談開始
- 「おすすめの重点」「気になる商品種類」「売場の回り方」等の適応的な質問
- 選択式、キーボード入力、対応ブラウザでの音声入力
- 既存推薦結果を壊さない後段再ランキング
- 「相性重視」と「新しい組み合わせを発見」の明示的な分離
- 推薦理由、複数商品の店内ルート、匿名イベント計測
- 来店客向け表示とスタッフ向け根拠表示

### 初版では実装しない

- OpenAI等の外部生成AIへの必須接続
- ニトリ既存チャットボットへの実接続（接続先・認証・仕様が未提供のため）
- POS・在庫・会員情報の実データ連携
- 会話ログを使った無審査のオンライン学習
- 商品データに存在しない「子ども向け」「手入れしやすさ」等を推測する質問

## 4. データ上の判断

現行 `data/products.json` は価格・分類・売場座標を全件で持つ一方、色は一部商品にしか存在しない。そのため、価格・分類・売場は安定した再ランキング条件として使い、色の質問は候補内の値が十分に揃った場合だけ表示する。欠損データで質問を固定表示しないことを、見かけだけのパーソナライズを防ぐ受入条件とする。

併売・座標・売場データには検証用の仮想値が含まれる。したがって、画面では「売上向上が証明済み」と表現せず、提案理由と検証用データであることを区別する。実店舗導入時は、同じスキーマへ承認済み商品・POS・在庫データを差し替え、オフライン評価とA/B検証を行う。

## 5. 推薦方針

1. 既存 `PersonalizedRecommender` が併売リフトとコーディネート適合度から候補を生成する。
2. ガイド型チャットは候補集合を新しく捏造せず、来店客の回答に基づいて後段で再ランキングする。
3. 「相性重視」は既存スコアと同一コーディネートの商品を優先する。
4. 「価格重視」は候補内の相対価格を使う。
5. 「新しい組み合わせ」は `high_lift_low_corate`、すなわち関連性がある一方で現状の併売率が低い候補を明示的に押し上げる。
6. 各回答が実際にスコアへ反映されない質問は表示しない。

この設計により、「既に売れやすい商品だけを返す」経路と「関連性を保ちながら未開拓の組み合わせを探索する」経路を、利用者の意図に応じて切り替えられる。

## 6. プライバシーと運用

- 会話状態はフロントからAPIへ渡す短期状態とし、自由入力本文はイベントログへ保存しない。
- イベントには質問ID・選択肢ID・提示商品ID等の非個人情報だけを保存する。
- 価格・在庫等の変動情報を言語モデルへ学習させず、常に商品データ/APIを真実源とする。
- 将来ニトリの既存Botへ接続する場合も、画面と会話APIの契約を維持し、応答生成部分だけを差し替える。

## 7. 成功判定

初版の成功は「チャットが動く」だけでは判定しない。少なくとも以下を分けて見る。

- 操作性: 初回応答時間、質問完了率、途中終了率
- 行動: チャット推薦商品のタップ率、複数商品ルート到達率
- 売場: サブ通路経由率、対象売場への到達
- 事業: POS突合後の同一空間併売率、買上点数、客単価

イベント差だけで併売率向上を断定せず、実POSとの突合と正しい実験群割付を導入判断の条件とする。
本統合版の treatment は「既存Room Harmony＋ガイド型チャット」、control は「既存Room Harmonyフロー」である。両群とも基礎推薦を使うため、controlをシステム完全非利用群とは呼ばない。
